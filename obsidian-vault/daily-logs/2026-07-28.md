## What I worked on

**Set out to fix the export defect the morning's build review found, and
disproved it instead.** The review's headline — that the first binaries in
project history ship with no game data and boot into an error storm — is wrong.
The pack was always complete. What was real was the *other* half of the same
finding: 244 development-only files were being shipped to players, and the CI
smoke test could not tell a healthy build from a broken one. Both are now fixed,
along with a `.gitignore` rule that would have silently prevented the fix from
reaching CI. Then pinned CI to the exact engine patch, and worked out what it
actually takes to produce a macOS binary — which turned out to be less than
expected, because a launchable one already exists.

No game-logic code changed. B3 (the span defect) is still unimplemented.

## What got done

- **Disproved B1.** The shipped `wildlife-crossing.pck` from the 2026-07-27 CI
  run contains **all 20** `data/*.json` files. Booted it directly with
  `godot --headless --main-pack`: three lines, `Tutorial loaded`, no errors,
  runs until the timeout. The artifact was never hollow.

- **Found why the review got it backwards.** Godot 4.6 writes **pack format 3**,
  which stores paths *without* the `res://` prefix and moves the file directory
  to the end of the pack. The review scanned the pack for `res://…` strings, so
  it could not see the directory at all — while still matching path literals
  embedded in compiled `.gdc` bytecode and the global class cache. Those
  literals are where the "236 `addons/gut/` paths" came from. The scan therefore
  reported the exact inverse of the truth: no data, lots of GUT.

- **The review's reproduction was circular.** Copying `game/` *without* `data/`
  and observing an error storm demonstrates what a data-less build looks like.
  It does not establish that this build was one. Worth naming, because the
  reproduction is what made the diagnosis feel confirmed.

- **`export_filter="all_resources"` was never the problem.** Godot 4 registers a
  JSON resource loader, so `.json` *is* a resource and is packed by that filter.
  The premise that Godot treats it as a plain file is a Godot 3 fact. I did try
  the proposed `include_filter="data/*.json"` fix first; it changed nothing,
  because there was nothing to change. Reverted.

- **V2 was real, and is fixed.** The shipped pack carried **213 `addons/gut/`
  and 31 `tests/` paths** — confirmed from the pack directory, not from a string
  scan. Added `exclude_filter="addons/gut/*,tests/*"` to all four presets:
  370 files → 77, **1.64 MB → 165 KB**, and the result still boots clean. This
  is the one genuine export defect of the pair.

- **B2 — rewrote the smoke test as [`tools/smoke_boot.sh`](../../tools/smoke_boot.sh).**
  A script rather than inline YAML so it can be tested, and it was: green
  against a healthy boot log, red against a data-less one, naming all four fault
  patterns and their counts. Two things it had to get right, both discovered by
  measurement rather than reasoning:
  - **A healthy boot does not exit.** The game has no auto-quit, so `timeout`
    stops it and the exit code is **124**. The review's proposed acceptance
    criterion — *"fails if the binary does not exit before the timeout"* — would
    have failed every good build.
  - **Exit code cannot discriminate.** A data-less boot *also* ends at 124,
    after 11,601 lines of errors. Only the content checks do real work.

- **V1 — [`tools/check_pck_contents.py`](../../tools/check_pck_contents.py) +
  [`tools/inspect_pck.py`](../../tools/inspect_pck.py), wired into CI.** A real
  pack-format parser (formats 2 and 3), not a string scan. Derives the expected
  file list from `game/data/` so a new data file extends the guard automatically.
  Verified three ways: passes on the fixed pack, fails on the old one for
  shipping GUT, fails on a deliberately data-stripped one for missing all 20.

- **Caught a `.gitignore` rule that would have quietly broken all of this.**
  `/tools/` was ignored, so the three new CI scripts would never have been
  committed and every CI run would have failed on a missing file. Git cannot
  re-include a file whose parent directory is excluded, so the pattern is now
  `/tools/*` plus `!/tools/*.py` / `!/tools/*.sh`. The vendored Godot binary
  stays ignored.

- **Gitignored `wildlife-crossing-desktop-builds/`** (review V3) — 232 MB that a
  `git add -A` would have committed against the stated releases policy.

- **Pinned CI to `4.6.3-stable`** (was the `4.6-stable` series, which resolved to
  **4.6.0** on the runner while the vendored `tools/` binary is **4.6.3**). Four
  places in `ci.yml` — the env var plus both job names, which inline the version
  because the `env` context is unavailable there — with ADR 0012 amended and
  `testing-setup.md` corrected. Verified the template-directory derivation
  (`godot --version` → `4.6.3.stable`) against the real 4.6.3 binary.

- **`project.godot` lost its hand-written comments again**, stripped by my own
  `--import`/`--export-pack` runs. Restored to match `HEAD` exactly.
  **The 2026-07-27 conclusion was wrong:** moving the comments "above Godot's
  block" does not protect them. Godot's config writer emits only its own
  boilerplate header and drops every comment wherever it sits — the ETC2 comment
  was in the file *body* and went too. The settings always survive; only the
  comments are lost. The ETC2/universal rationale now lives durably in
  [export-setup](../../docs/export-setup.md) instead.

- **Verified the existing macOS artifact is real, and B6 is closer than the
  review implies.** Unpacked
  `wildlife-crossing-desktop-builds/wildlife-crossing-macos/wildlife-crossing.zip`:
  a proper `.app` bundle, 7 files, a **universal Mach-O** (x86_64 + arm64),
  ad-hoc signed (`_CodeSignature/CodeResources` present — which matters, because
  Apple Silicon refuses wholly unsigned binaries), and its pack contains **all
  20** data files. It is the pre-fix pack (370 files, built by Godot **4.6.0**),
  so it still carries GUT, but it should launch as-is after
  `xattr -dr com.apple.quarantine`. The quarantine step is needed because the zip
  was *downloaded*; a locally-built export will not need it. Wrote the local
  export route up in [export-setup](../../docs/export-setup.md) — the missing
  piece there is still the templates `.tpz`, not the editor.

- **Suite still 15 scripts / 116 tests / 2,740 asserts green.**

## Decisions made

- **Amend the build review rather than rewrite it.** B1 is marked withdrawn in
  place, with the evidence, and the index headline is corrected. Same treatment
  ADR 0003 got on 2026-07-19. A review that was wrong is a useful record; a
  review silently corrected is not.

- **No `include_filter` on the presets.** It is not what makes the data ship, and
  adding config that appears to fix a defect which never existed would mislead
  the next person as badly as the original scan did. The contents guard is the
  honest protection.

- **`ERROR:` is a hard failure in the smoke test**, not just the two specific
  "missing file" strings. If a benign `ERROR:` ever appears on a CI runner it
  gets allowlisted explicitly. A gate that cannot fail is what produced this
  whole episode.
