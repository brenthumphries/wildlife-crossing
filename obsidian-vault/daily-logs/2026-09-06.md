## Decisions made

- **No bypass actor on the ruleset, Brent's call.** The alternatives were an
  admin break-glass, which keeps `docs/push-runbook.md` working unchanged, and
  checks-only with direct pushes still allowed. Both were rejected on the same
  ground: [ADR 0019](../../docs/adr/0019-dco-sign-off-on-automated-commits.md)
  signs machine-written commits off in advance partly because nothing signed in
  advance can reach `main` without a human merge click, and on 09-05 that
  guarantee was enforced by habit. An admin bypass leaves it enforced by habit.
  The cost is real and was accepted: the runbook needed rewriting, and there is
  no terminal hotfix path to `main`.
- **All five checks required, with the section 6.2 fix landing first.** The
  alternative was requiring the three that cannot be skipped and leaving
  `export` and `smoke-windows` advisory, which would leave the Windows binary,
  the one nobody here can launch by hand, ungated at merge.
- **Reorder the Step 5 checklist rather than rebind F1.** Credits are reachable
  twice by different code: the menu button through `title_screen.gd` before
  Play, `main.gd`'s `CREDITS_KEY` after it. Deleting either check would drop a
  live route, so both are checked and the keyboard one moved after Play.
- **Zero required approving reviews, and no required signatures.** GitHub does
  not let an author approve their own pull request, so a 1 makes every pull
  request on a sole-maintainer repository unmergeable. Required signatures
  would fail ADR 0019 runner commits, which are signed off rather than GPG
  signed.

## Open questions / blockers

- **The gate has never refused anything.** Both pull requests under it were
  merged after their checks were already green, so the ruleset was satisfied
  rather than exercised. Its refusal path is unverified until a check goes red.
  Two clean merges are not evidence that it blocks.
- **`ci.yml:275` doc drift is now load-bearing.** This note's §4 records the
  `smoke-windows` job name as cosmetically wrong: it says "boots to Main.tscn"
  while `run/main_scene` is `TitleScreen.tscn`. That job name is now a required
  status check context. Renaming it without editing
  `.github/rulesets/protect_main.json` in the same commit produces a context
  that never reports, which under an empty `bypass_actors` is an unmergeable
  pull request rather than a red one. The same trap applies to any
  `GODOT_VERSION` bump, since two of the five contexts carry the version string;
  the `env:` comment in `ci.yml` now says so.
- **`require_extra_approval_for_unattributed_changes: true` arrived by
  default.** It was not in the file that was posted. GitHub's documentation
  scopes it to Copilot opening a pull request under its own app identity, where
  it requires one approval more than configured. It did not fire on #5 or #6,
  both authored by Brent, and it is not a deadlock even if it does, since he can
  approve a pull request he did not author. Untested against the ADR 0019
  pipeline.
- **Nobody has walked the corrected Step 5 checklist.** It has been unrunnable
  as written since 2026-08-09, so the first walk is also the first test of the
  ordering. Treat a failure there as possibly real rather than as the checklist
  being wrong again.
- **B8 is not closed by any of this.** The ruleset covers the branch-ruleset
  line in its Files/areas, and goes further than the 08-29 decision scoped by
  also requiring a pull request and the checks. Its acceptance is untouched: no
  credential patterns in `.gitignore`, secret scanning and push protection
  unconfirmed, and the `git rm --cached export_presets.cfg` pre-flight not
  written into the signing runbook.
- **This log is uncommitted**, along with the amendment to
  [[../build-reviews/2026-09-01-next-build]] and its index line in
  [[../build-reviews/README]]. Nothing else in the working tree is dirty.

## Also this session: two operational findings

- **The 09-05 checkout trap fired again, and the guard written for it was aimed
  at the wrong file.** `git checkout main` aborted on
  `obsidian-vault/daily-logs/2026-09-05.md`. The session had checked `ci.yml`
  for divergence between the branches and cleared it, which was the wrong test:
  the file to suspect is whichever one the current branch's own commit touched.
  `a828a6d`, the single commit on `docs/log-merge-addendum`, is what edited
  `2026-09-05.md`, and local `main` did not have it yet. `git stash push`,
  checkout, pull, branch, `git stash pop` recovered it with no conflict.
  Untracked files are not stashed by that and did not need to be.
- **`gh pr checks --watch` races pull-request creation.** Chained straight
  after `gh pr create` on PR #5, it printed `no checks reported on the
  chore/protect-main branch` and exited. The run was queued and went on to pass
  all five. Worth the line it now has in Step 3 because of how it reads at the
  time: it is the last output of a paste that just created a pull request, it
  names the branch, and under a freshly protected `main` the natural next
  thought is that the gate is misconfigured. `014ed0c`.
