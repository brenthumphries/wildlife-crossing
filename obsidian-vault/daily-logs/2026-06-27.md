## What I worked on

Authored the Y2Y world map as a runtime game asset: the `sub_areas.json` data
file backing the top-level world map in the crossing-location-selection
workflow. Scope was clarified up front with the product owner before any work
began — deliverable form, breadth, and how to handle the spatial layout gap.

## What got done

- Reviewed the governing docs: [[crossing-location-selection]] (the interface
  that consumes sub-area data), [[sub-areas]] (the definitive 12-region list and
  sizing/naming rules), [data-schemas.md](../../docs/data-schemas.md) §4 (the
  normative schema + stub table), [[art-direction]] (locked/desaturated
  treatment), and [ADR 0002](../../docs/adr/0002-hex-grid-topology.md) /
  [ADR 0004](../../docs/adr/0004-connectivity-patch-adjacency-graph.md).
- Created **`game/data/sub_areas.json`** (`data_version: 1`) with all twelve
  sub-areas, strictly conforming to the §4 field table — first real file in the
  previously `.gitkeep`-only `game/data/`.
- Wrote a validation pass (JSON parse + §4 types + §11 checklist) that runs
  clean: 12 entries, all required fields present/typed, every
  `controlling_entity_id` resolves to the nine-entity roster, only sub-area 7
  starts unlocked, all tile counts within ±15% of the 4000 target.

## Decisions made

- **Deliverable = the data file, world-map level only, strictly schema-conformant**
  (product-owner choices via clarifying questions). No Godot render scene, no
  visual map, no segment/connectivity data, and **no schema extension** — the
  sub-area schema has no position/geometry fields, and spatial placement was
  deliberately left to the renderer/later work rather than drifting the schema.
- **Sub-area 7 (Central Canadian Rockies)** uses the canonical sample object from
  the schema spec verbatim (`trust_threshold: 0`, `starts_unlocked: true`) — the
  start region per the documented trust-pacing decision.
- **Peace River Break (8)** is the only entry carrying a `size_deviation_note`,
  documenting that its narrow real geography is compensated by denser playable
  tiles to hold the ~4000 target (the "normalize playable density, not geographic
  truth" rule from [[sub-areas]]).
- **`indigenous_name_note` populated for sub-areas 9 and 11** (Muskwa–Kechika;
  Stikine–Nass–Skeena) — the two whose *names* are of Indigenous origin. Notes are
  measured, name origins + overlapping traditional territories only, and each is
  explicitly flagged **pending cultural-advisor review** per
  [[cultural-narrative-design]]. All other entries are `null`.

## Addendum — P0 blocker resolution session

Picked up the P0 resolution order and worked it end to end through the simulation
chain, resolving six blockers plus one cross-doc inconsistency. Each resolution
followed the same loop: ground in the governing docs, confirm the genuine design
calls with the product owner, write an ADR, wire the constants/schema, then
validate the decision programmatically against the Bow Valley fixture before
marking it resolved in [p0-open-questions.md](../../docs/p0-open-questions.md).

### What got resolved

- **A1 — world terrain layout → [ADR 0006](../../docs/adr/0006-world-map-authoring.md).**
  Maps are authored as data (`data/world/<sub_area>.json`: axial `[q,r]` tile-id
  grid + `origin`); the `TileMapLayer` is generated at load and never read back
  (one-way `data/` → tilemap), so the `tiles.json` registry stays the single
  source of truth. Reconciled the architecture §1/§3 static-vs-tilemap
  contradiction. Added the schema as [data-schemas](../../docs/data-schemas.md)
  §12 and authored the test fixture
  `game/tests/fixtures/bow_valley_slice.json` (also the **A9** answer).
- **A2 — patch compatibility → [ADR 0007](../../docs/adr/0007-patch-derivation-biome-compatibility.md).**
  Patch identity is biome-based and species-agnostic (ADR 0004's cheap graph
  preserved); viability is species-relative, over the connected network restricted
  to the species' habitat biomes (`network.total_tile_count()` →
  `habitat_tile_count(species)`). Tight biome groups authored in
  `game/data/biome_groups.json` (data-schemas §13) — which **also resolves B4**
  (the orphaned `biome_definitions.json`).
- **A6 — habitat-quality sub-formulae → [ADR 0008](../../docs/adr/0008-habitat-quality-subformulae.md).**
  Exact expressions for `terrain_base`, `size_factor`, `connectivity_bonus`,
  `edge_penalty`, kept orthogonal so a crossing raises quality purely via
  `connectivity_bonus`. New size/connectivity constants added.
- **A3 — animal existence & persistence → [ADR 0009](../../docs/adr/0009-population-seeding-and-agent-rendering.md).**
  Authoritative `count` and rendered agents decoupled; habitat-derived seeding;
  demographics change only monthly/seasonally (no free spawning); a capped
  representative agent pool; watched deaths are observable but not demographic.
- **A4 — pre-season goal selection → [ADR 0010](../../docs/adr/0010-pre-season-goal-selection.md).**
  Season-independent forage/wander drive with quality/distance-weighted goals;
  hazard attempts are emergent (A* risks a hazard only when no safe route exists),
  so fragmentation is the sole cause of unassisted death. Phase 4 seasons scale one
  parameter (`MOTIVATION_DISTANCE_MULT`).
- **A5 — capacity, recovery, decline → [ADR 0011](../../docs/adr/0011-carrying-capacity-recovery-decline.md).**
  One base capacity (size × quality), used ungated for seeding
  (`_potential_capacity`) and viability-gated for the monthly ceiling
  (`_carrying_capacity`); proportional recovery; gentle fixed `DECLINE_STEP`;
  re-establishment from zero via immigration. Defined the previously-missing
  `DECLINE_STEP` constant and reconciled A3's seeding to the ungated capacity.

### Decisions made (product-owner calls)

- A1 data-as-truth over editor-painted tilemaps; tiny hand-authored tutorial
  fixture over the full ~4000-tile map.
- A2 biome-based patches + species-restricted viability; tight ecological biome
  groups (not coarse macro-habitats or singletons).
- A6 `size_factor` measures the patch alone (orthogonal to connectivity);
  `connectivity_bonus` weights links by count **and** quality.
- A3 deaths decoupled from the authoritative count; starting populations
  habitat-derived rather than hand-authored per sub-area.
- A4 quality/distance-weighted stochastic goals; purely emergent hazard attempts
  (no base random-risk term).
- A5 proportional recovery (decelerating) over fixed linear; capacity reflects
  habitat size **×** quality, so crossings raise the ceiling.

### Validation

All decisions were checked programmatically on `bow_valley_slice.json` and
interlock as one system:

- Patch derivation yields two 120-tile forest patches + an 8-tile alpine patch;
  grizzly is sub-viable per side (128 / 120) and viable (248) once a crossing
  joins them.
- Habitat quality: west forest patch Fair (47.9) isolated → Good (53.4) after the
  crossing adds a safe link; clamp `[0,100]` and four-band mapping hold.
- A* goal routing: a west→east goal crosses 2 road tiles (~64% survival) before the
  overpass, then routes through the zero-mortality chain at lower cost (24→17).
- Population trajectory: grizzly seeded 18/side, declines 18→6 over six months while
  fragmented, then recovers 6→…→31 toward capacity 32 after the crossing, with the
  east patch re-establishing 0→2 from immigration. Counts stay within
  `[0, capacity]` throughout.
