## Decisions made

- **Fix the data boundary, not the two call sites.** Brent's call, from three
  facts checked first: `sub_areas.json` is the only numeric-id data file, so the
  blast radius is one dictionary; `world_select_controller` is the only consumer
  of `registry.sub_areas` anywhere in `game/`; and the controller has to key
  `_unlocked` by `int` regardless, because `unlock_sub_area()` and EventBus's
  `sub_area_unlocked` both deliver ints. `int` is the canonical type across every
  numeric id and signal in the codebase, and `_index()` was the only place
  producing anything else. Patching the consumer was rejected because it would
  leave `_sub_areas` float-keyed against an int-keyed `_unlocked`, two key types
  in one object, and leave the trap for the next numeric registry. Changing the
  data to string ids was rejected outright: it would touch `segments.json`, the
  `world/sub_area_%d.json` filenames, save files and eight signal signatures.
- **Coerce the record's `id` field as well, not only the key.** No production
  code reads a sub-area record's `id` field today, so that half was latent rather
  than live. Two extra lines closed it while the file was open.
- **Commit the vault backlog behind the fix in the same push.** `ship.py` refuses
  a plan that does not account for every changed path, so the seven owed files
  had to be claimed or stashed. Claiming them cost one extra commit and cleared
  the second item on the `/next` list.

## Also this session: two operational findings on the Cowork mount

- **`git checkout -- <path>` cannot restore a file over the mount.** It fails
  with `unable to unlink old '<path>': Operation not permitted`, leaves the
  working copy unchanged, and prints that as a warning rather than an error. The
  first revert check today ran against the unreverted file and reported a false
  pass. Caught it on the assert counts, then reverted by writing the old content
  back with Python. To A/B a file over the mount, copy it aside outside `mnt/`
  and write content back in place; never rely on `git checkout --`.
- **Each `ship.py` dry run leaves a fresh `.git/index.lock`** that blocks the
  next one, because the mount forbids `unlink`. `mv` clears it where `rm`
  cannot. Both are consistent with the 2026-08-11 root cause, which the 09-01
  review had recorded as unproven. Twenty-eight parked locks from this and prior
  sessions are now in `.git/_stale_locks/` and can be deleted from the Mac.

## Also this session: the automated development pipeline

### What got done

- **Designed the pipeline from roadmap to build log.**
  [pipeline-design](../../docs/pipeline-design.md), status `draft`. Eight stages
  carry a roadmap item through task generation, three parallel prototypes,
  automatic selection, build-out, review and merge, then back into this log.
  State lives entirely in GitHub Issue labels, so there is no store that can
  drift from the repository. Two points need a human: releasing a task for
  automated development, and reviewing the pull request.
- **It runs in GitHub Actions because the mount forces it.** `origin` is SSH,
  the Cowork mount has no keys, and `ship.py --execute` refuses to run over the
  mount, so the write side of every change currently ends at a keyboard. A
  runner has none of those problems. `ship.py` stays as the guard on the local
  path and stops being the only path.
- **Two constraints in the existing CI shaped the design.** The `dco` job
  rejects every commit a runner would write, settled by ADR 0019 below. And the
  artifact upload is `if: always()` while `smoke-windows` declares
  `needs: export`, so any upload failure fails the export job and blocks an
  unrelated merge. That cascade, not the storage quota, is what did the damage
  on 2026-08-27. Going public removed the quota and left the cascade armed.
- **ADR 0019, DCO sign-off on machine-written commits.**
  [0019](../../docs/adr/0019-dco-sign-off-on-automated-commits.md). Written
  because `check_dco.py` would fail every automated pull request on arrival, so
  nothing else in the pipeline can exist until it is answered.
  `CONTRIBUTING.md` gains a "Machine-written commits" subsection pointing at it.
  Neither `check_dco.py` nor the `dco` job changes.
- **The project-state board moved to a hosted artifact, refreshed daily by a
  scheduled cloud session** reading this repository over the public API. It was
  seeded from the 09-01 review and this log: build case, the 24 / 246 / 3,154
  suite, head at `829e36b`, five open blockers with B3 struck through, and the
  next actions in the order this log put them.
- **Found a defect in the weekly-build-review harness by asking where that
  refresh would run.** Step 7 calls `list_artifacts` and `update_artifact`,
  which exist only in a session linked to the Mac. It has always been a
  Mac-only step inside a skill that reads as machine-independent, and it is the
  only part of that skill that cannot run on a runner. Deletion is owed.
- **Recorded what going public changes for the pipeline.** Fork pull requests
  get no secrets, so automated pre-review cannot run on an outside
  contribution. The action requires write access on issue and pull-request
  events, so a stranger cannot make Claude run. Scheduled workflows are
  disabled after 60 days of repository inactivity, which would stop the task
  queue silently rather than with an error.

### Decisions made

- **Automated commits are authored by and signed off by Brent, with a
  `Co-Authored-By: Claude` trailer.** Brent's call. The reasoning is that the
  DCO certifies provenance and the right to submit, not authorship of every
  line and not review, and provenance is a fact about how work is produced.
  ADR 0017's finding that machine output is uncopyrightable helps rather than
  hinders here: no other rights-holder's permission is needed. Rejected: a bot
  identity signing as itself, which `check_dco.py` would pass while it
  certifies nothing, and merge-time sign-off in the squash message, which is
  the more honest record but needs `feat/**` commits exempted from the `dco`
  job and a replacement main-push check scoped past the 33 unsigned legacy
  commits. The honest objection, that the trailer predates the review, is
  recorded in the ADR rather than argued away.
- **The dashboard refreshes daily rather than weekly, and guards its own
  work.** Weekly was wrong because the inputs change two or three times a week:
  a Monday page would have shown 23 / 237 / 3,032 and six blockers all week.
  The run compares the head SHA already baked into the page against `main` and
  stops if nothing moved.
- **"State as of" and "last verified" are separate stamps on that page.** A
  guarded run otherwise has only bad options: leave the date old and a reader
  cannot tell stale from unchanged, or advance it and the page claims freshness
  it did not earn. A page that is accurate and eight days old is fine. A page
  that silently claims to be current is not.
- **Prototype breadth is three shallow spikes, then one proper build.** Brent's
  call, against two full attempts (roughly double the cost, one thrown away)
  and against an options memo with no code (judges designs on paper rather than
  on whether they compile).
