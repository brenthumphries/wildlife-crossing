## What I worked on

**First hands-on play session on Brent's Mac** — and it immediately earned its
keep. Getting the game launching locally surfaced a Phase 1 correctness defect
that 114 passing tests could not have caught, because the tests encode the same
misreading the implementation does. The session went: get it running → play it →
describe what looked wrong → diagnose → document → fix the small adjacent bug →
answer the design question the defect opened.

No game-logic code changed. The defect is fully specified but not yet
implemented.

## What got done

- **Got the game running on macOS.** The `tools/` Godot binary is Linux arm64
  (sandbox/CI only) and `builds/` has no macOS export, so the path is: install
  Godot **4.6.3** for macOS, open `game/project.godot`, F5. Documented the
  controls (B build, M map, click select) and the calibration a first-time
  player needs — everything is the placeholder colored-circle renderer, there is
  no HUD, and **all feedback goes to `print()`**, i.e. the editor's Output
  panel, not the screen. That last point is why the game felt mute.

- **Found the segment/span defect.** Pressing B turned the entire Bow Valley
  highway yellow — the road stopped existing rather than being bridged.
  `build_full()` covers *every* dangerous tile in a segment (all 20), when the
  PRD means the width at the crossing point (2). Written up at
  [[../design/segment-vs-span-defect]].
  - The PRD says **width** throughout ("the full width of the dangerous
    terrain", "a three-tile-wide river requires three overpass tiles").
  - The cost arithmetic is decisive: at 5,000/tile, current behaviour prices the
    *tutorial* crossing at **100,000** against a **50,000** starting budget.
    Correct behaviour: 10,000.
  - Root cause: the code has one word for two things. A **segment** is the whole
    hazardous corridor (unit of *selection*); a **span** is the structure across
    it (unit of *construction*).

- **Amended the documents that caused it.** PRD rule 2 reworded so "span every
  cell of dangerous terrain" can no longer be read as "every cell of the
  segment", plus the proposed-solution paragraph and the pathfinding-graph P0
  acceptance criterion. [ADR 0003](../../docs/adr/0003-crossing-tile-architecture.md)
  carries an amendment — it repeated the same phrase and propagated the error.

- **Answered the diagonal-corridor question → [ADR 0016](../../docs/adr/0016-crossing-span-geometry.md).**
  "Width" presumes an axis that `s1_snake_river_a` (an 8-tile diagonal stair)
  does not have. Replaced with a topological definition: a span is a connected,
  single-type set of hazard tiles containing a subset whose *safe ring* falls
  into two or more components. Shape-agnostic. Verified against the real data —
  Bow Valley → 2 tiles (10,000), Snake River → 1 tile (5,000); a half-width span
  and tiles laid *along* a corridor both correctly rejected.

- **Fixed the camera offset.** `main.gd` framed the opening view with raw
  `coord * TILE_PX` while the renderer projects through a *sheared* hex basis —
  72px off in x. The projection turned out to be copy-pasted in **three** places
  (renderer, connectivity overlay, and the test), so it is now one static
  `WorldRenderer.px_at_coord()` and the overlay delegates to it. Added
  `class_name Main` and named `CAMERA_FOCUS_COORD` / `CAMERA_ZOOM` constants.
  **Suite: 15 scripts / 116 tests / 2,740 asserts, all green** (was 114).

## Decisions made

- **Player picks the span location.** Rejected auto-placing at the
  highest-connectivity point (ships fastest, but placement is the central verb of
  the game and shouldn't be automated away) and authoring a fixed location per
  segment (most faithful, cheapest, but 19 segments to hand-author and no player
  agency). Matches the PRD's existing build-palette language.

- **Over-wide spans are priced, not policed.** Cover more than the minimum and
  the span is valid — you just pay per tile. Rejecting it would mean an error
  message for a harmless act, against the "cozy, not stressful" north star. *This
  was my recommendation adopted, not a consequence of the geometry — the one
  overturnable call in ADR 0016.*

- **Validity is "contains a two-sided core", not "is two-sided".** The direct
  test is not monotone: covering the whole Snake River reads as one-sided
  (rejected) while covering the whole Bow Valley road reads as two-sided
  (accepted) — the same player action judged oppositely. Requiring only that a
  valid core exist inside restores monotonicity.

## Open questions / blockers

- **The defect is documented but not fixed.** `try_complete()` still paves whole
  segments. Scope is three files — `infrastructure_manager.gd` (the real change),
  `simulation.gd` (one-line passthrough), `infrastructure_manager_test.gd`
  (assertions encode the wrong behaviour). Pathfinding, the connectivity graph,
  and the data schema are untouched; `_chain_connected()` is already the needed
  primitive.

- **Will animals even use a crossing?** New and larger than the defect itself —
  tracked at [[../design/detour-cost-question]]. Only **2 of 19** segments
  (Bow Valley, Pine Pass) cut their map in two; the rest stop short, so an animal
  can walk around the end. Every segment is `is_hazardous`, none `is_impassable`,
  so roads never block — they only kill. Whether a crossing gets used therefore
  depends on detour cost vs. mortality-weighted crossing cost, which is unmeasured.
  Bow Valley does separate, so the tutorial should demo correctly either way.

- **GUT reports success while silently dropping a whole test file.** Hit while
  adding `class_name Main`: the referencing test failed to parse, GUT printed
  `---- All tests passed! ----` and exited **0**. The only signal was the script
  count falling 15 → 14. The V1 guard from [[2026-07-10]] catches a *zero*-test
  run but not a partial drop, which looks healthy. Worth a CI assertion on
  expected script count.

- **`class_name` needs a re-import.** Adding one to a script doesn't reach
  `.godot/global_script_class_cache.cfg` until `--headless --import` runs;
  anything referencing it fails to parse until then.
