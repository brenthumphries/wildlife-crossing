## What I worked on

**Cleared B1 and went hunting for the first binary.** The session started as a
walkthrough of outstanding work from the logs and the 2026-07-21 build review,
and turned into a CI archaeology dig. B1 landed — six commits, pushed. Then V2
answered itself in the worst way: CI has **never** gone green, not once, and the
artifact everyone assumed might be sitting in the 2026-07-11 run never existed.
Diagnosing that turned up a build that had been succeeding and being thrown away
for sixteen days.

No game-logic code changed. The span defect ([[2026-07-19]], B2) is still
unfixed.

## What got done

- **Verified the 2026-07-21 review against the code before trusting it.** Six
  days old, and nothing had moved: `HEAD` still `af85bce`, `try_complete()`
  still looping every dangerous tile, no hover code, no HUD, no sprites, no
  tags, `builds/` empty. The whole list carried forward intact.

- **B1 — committed and pushed the 2026-07-19 working tree.** Six commits,
  `af85bce` → `9ba62e2`, grouped so each is reviewable alone: the
  gitignore/untrack housekeeping, the camera-projection fix, ADR 0016 plus the
  ADR 0003 and PRD amendments, the two design memos, the daily logs, and the
  harness plus build-review notes. Written up as a step-by-step runbook at
  [b1-commit-runbook](../../docs/b1-commit-runbook.md).

- **Found `project.godot` had silently regressed.** Opening the project in the
  Godot editor stripped the hand-written header — the ADR 0012 pin rationale and
  the `architecture.md` pointer — and replaced it with Godot's boilerplate.
  Restored above Godot's block so both survive the next editor save.

- **Untracked the Obsidian pane state.** `.obsidian/workspace.json` was 71 of
  the 210 changed lines — a third of the diff was window layout. `.gitignore`
  covered `obsidian-vault/.obsidian/` but not the one at repo root.
  `app/appearance/core-plugins` stay tracked so shared config still syncs.

- **V2 — answered, and the answer is worse than assumed.** All three CI runs in
  history are failures. The 2026-07-11 run that the review hoped might have
  produced a downloadable artifact **failed the same way this one did**; there
  was never anything to expire. `gh run download` confirmed it: no valid
  artifacts, ever.

- **Diagnosed the export failure.** Not the version pin — that was my first
  guess and it was wrong; templates install cleanly. The macOS preset is
  `binary_format/architecture="universal"`, and Godot refuses to export
  universal or arm64 with ETC2 ASTC disabled. `project.godot` had no
  `import_etc2_astc` setting at all, so it defaulted off. Byte-identical error
  on 2026-07-11 — one stable defect, not a regression from B1.

- **The build already existed, twice over, and was being deleted.** Reading the
  log's three Godot invocations: Linux x86_64 and Windows x86_64 both reach
  `[ DONE ] savepack`. Only the third fails, at config validation, *before*
  packing. Because the step runs under `set -euo pipefail` it aborts there, so
  the smoke test and the artifact upload never ran and two finished binaries
  went into the bin with the runner. Every run since 2026-07-11.

- **Fixed it in three places** (`62a4a48`): `import_etc2_astc=true` in
  `project.godot` (the actual gate), `texture_format/etc2_astc=true` on the
  Linux arm64 preset (same latent failure, would bite whoever exports it), and
  `if: always()` on the upload step so one bad preset can never again discard
  good binaries.

- **First artifacts in project history.** On `62a4a48` the *Export desktop
  presets* step went green for all three platforms and *Upload build artifacts*
  succeeded. Linux, Windows and macOS builds now exist and are downloadable.

## Decisions made

- **`fable-game-builder/` is gitignored, not committed.** It is a generic Godot
  project-builder toolkit — skills, agents, templates — not game content.
  Keeping the monorepo about the game; it stays on disk and can be extracted to
  its own repo later. Rejected committing it (grows repo scope) and leaving it
  untracked (re-flagged by every future review).

- **`harness/` is committed.** `build-reviews/README.md` already documented it
  as the way to run a review, so the reference pointed at something the repo
  didn't contain. 32K, and it makes the review process reproducible.

- **Pushed without running the suite locally.** Godot isn't installed on this
  Mac — `mdfind` and `/Applications` both came up empty, despite the 2026-07-19
  session having had it running. Steps 1–4 of B1 touch no game logic, and CI
  runs the same suite, so a missing local install was not worth blocking the
  thing every other item depends on. CI confirmed green: *GUT tests* passed on
  both pushes.

## Open questions / blockers

- **The smoke test fails: "exported binary did not boot to the tutorial."**
  New, and it is the only thing between here and B4. The logic reads correct —
  `main.gd:58` calls `_log()` → `Debug.info()` → `print("[I] ", msg)`, and CI
  greps a substring, so the `[I] ` prefix should not break the match. Needs the
  step's echoed `$OUT` to distinguish: empty (binary never ran), Godot banner
  then nothing (booted but `_ready()` died before line 58 in a release build),
  or a crash. **Not yet run.**

- **B4 is half-closed and needs the honest version stated.** Artifacts exist —
  that is genuinely new — but "a binary exists" and "a binary that boots" are
  different claims, and only the first is evidenced. The windowed launch on this
  Mac is still owed; the macOS zip is unsigned, so it needs
  `xattr -dr com.apple.quarantine` first.

- **`export_filter="all_resources"` ships the entire GUT addon and all 16 test
  scripts inside the release binary.** Not the cause of anything today, but it
  is dead weight in a shipped build and worth an exclude filter before v0.1.0.

- **Godot 4.6.3 needs reinstalling on this Mac.** Blocks the C3 visual QA pass,
  B4 route (b), and playing the game at all. Grab
  `Godot_v4.6.3-stable_export_templates.tpz` at the same time — it is the one
  missing piece for local exports.

- **Everything else from [[2026-07-19]] still stands:** B2 (the span defect) is
  documented and unimplemented, B3 (placement UI) depends on it, B5 needs an
  owner call on scope, and C1 — the visual cue and HUD — is still the difference
  between a binary that launches and one that can be played. All feedback still
  goes to `print()`, invisible in a windowed export.
