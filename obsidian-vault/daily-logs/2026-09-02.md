## Findings

- **The world map renders every sub-area locked, Bow Valley included.** All
  twelve cards grey, all twelve carrying the padlock glyph. Root cause,
  reproduced headlessly against the real `data/sub_areas.json` with the vendored
  4.6.3 binary:

  ```
  keys: [1.0, 2.0, 3.0]
  has(7.0)=true   has(7)=false
  get(7, false)   -> false
  get(7.0, false) -> true
  ```

  `JSON.parse_string` returns every JSON number as a float, so
  `species_registry.gd:52` (`out[rec[key]] = rec`) keys `sub_areas` by floats
  `1.0` through `12.0`, and Godot dictionaries treat `7` and `7.0` as different
  keys. `world_select_controller.gd:65` then iterates `for id: int in ids:`,
  which narrows `7.0` to `7`, so `sub_areas[id]` misses. The first probe raised
  the engine error on that line verbatim: `Out of bounds get index '1' (on base:
  'Dictionary')`. `_unlocked` never receives an entry that
  `is_sub_area_unlocked(sub_area_id: int)` can find, and `:232` has the same
  defect for card labels.
- **The suite cannot see it.** `world_select_controller_test.gd:11` hand-builds
  its fixture as `7: { "id": 7, ... }`, with int keys. No test feeds
  JSON-parsed data through `SpeciesRegistry` into this controller.
- **Blast radius is one feature.** `tiles`, `milestones`, `segments`, `entities`
  and `species` all use string ids, `infrastructure` is keyed by
  `crossing_type`, and `main.gd:120` guards itself with an explicit
  `int(seg.get("sub_area_id", -1))`. `sub_areas` is the only numeric-keyed
  registry, so this breaks exactly the look-only world map that Phase 2 ships.
- **All UI text is too small to read at the default window size**, credits
  included, and the world-map cards are small with it. `game/project.godot` has
  **no `[display]` section at all**, so the export runs on Godot defaults: a
  1152x648 viewport, `stretch/mode` disabled, scale 1.0. Nothing scales with
  window size or pixel density. Credits body is 13px
  (`credits_screen.gd:53`), the menu tagline 15px, and the HUD message line and
  crossing cue carry no font-size override at all (`hud.gd:28-42`), so they
  inherit the 16px default. The map draws 170x84 cards in a 3-column grid
  (`world_select_controller.gd:29-32`).
- **F1 is bound only in `main.gd`.** `push-runbook.md:302` puts "F1 opens
  credits" at Step 5.2, before "Start" at 5.3, and `title_screen.gd` binds no
  keys, so that step has never been runnable in the order written. Same defect
  class as the hardcoded `wildlife-crossing.app` name fixed on 2026-08-14. The
  runbook needs the ordering corrected.
- **The macOS application menu's About item does nothing.** It is Godot's
  default app menu, not ours: `main_menu.gd:78-84` builds exactly Play, Credits
  & Licences, Quit. A stranger's first click on the menu bar hits a dead entry.
  The same button reads "Licences" in an otherwise US-spelled project.
- **Escape leaving build mode entirely is not a regression.** `main.gd:149-151`
  routes Escape to `_cancel_build()`, which exits build mode wholesale, so
  re-pressing B is the intended behaviour. Whether it should be a per-tile undo
  is a design question, not a defect.

## Decisions made

- **Record the legibility finding, do not fix it this session.** Brent's call.
  The durable fix is a `[display]` block with a larger default window and
  `stretch/mode = "canvas_items"`, which scales every Control together, but it
  also scales the world render and changes screen-to-world coordinate mapping.
  That is the area `cb9f9b8` fixed for the blind-click bug, so it needs its own
  session with `world_select_controller_test.gd` re-run and a fresh export to
  verify. Bumping individual font constants was rejected as per-screen patching
  that leaves the next UI to rediscover the problem.
- **B3 closes with findings.** The checklist was walked to completion and the
  `codesign` evidence recorded. Two acceptance clauses failed on the way: the
  credits screen and the HUD message line were both required to be legible and
  neither is. Recording that as a closure plus two findings, rather than holding
  B3 open, because the item's job was the walk and the walk is done.

## Open questions / blockers

- **The float-key defect is untracked and unnumbered.** It belongs in the next
  review as a blocker rather than a core task. Phase 2's second exit criterion
  is `roadmap.md:116`, "Locked sub-areas desaturated with lock indicator", and
  the artifact desaturates and padlocks all twelve, including the one that must
  be unlocked. That is the **second** Phase 2 exit criterion met in tests and
  broken in the artifact a stranger runs, the first being C9. B6's release note
  cannot claim Phases 1 and 2 met while it stands.
- **The fix location needs an owner call.** Recommendation: coerce numeric ids
  to int inside `species_registry.gd` `_index()`, so every consumer is corrected
  at the data boundary, rather than patching the two lines in
  `world_select_controller.gd` and leaving the trap for the next numeric
  registry. Either way it needs a test that loads real `data/*.json` through
  `SpeciesRegistry`, since a fixture-based test is what missed this.
- **Two consequences unverified.** With no sub-area unlocked,
  `focused_sub_area_id` should fall through to `ids[0]`, which is sub-area 1 and
  not sub-area 7, so the white selection outline is probably on the wrong card.
  The exported binary should also be printing script errors on every world-map
  draw. Launching it from Terminal rather than `open` would show both.
- **C4 is still undecided**, 23 days after it was flagged. The walk confirmed
  the symptom: the cue fires and is legible as an event, and the crossing itself
  is off camera.
