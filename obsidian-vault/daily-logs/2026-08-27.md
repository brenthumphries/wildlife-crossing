## What I worked on

Diagnosing the previous night's CI failure, fixing its cause and V9 in the same
edit, and starting the Apple enrolment that four consecutive build reviews have
ranked first. Written mid-session; the CI change is not yet committed.

## What got done

- **Diagnosed the export failure. Nothing was broken.** The log's own lines
  settle it: `With the provided path, there will be 11 files uploaded`, then
  `##[error]Failed to CreateArtifact: Artifact storage quota has been hit.` All
  three presets exported and eleven files were staged. The failure was capacity.
  The account was on GitHub Free, whose included artifact storage is 500 MB,
  and `ci.yml:243` was uploading a full macOS plus Windows plus Linux set with
  a 14-day retention on every pull-request run and every push to `main`.
- **Named the cascade, which is the expensive part.** `upload-artifact` is the
  last step of `export`, so a failed upload fails the job, and `smoke-windows`
  takes `needs: export` and is skipped rather than run. B2's acceptance requires
  all five jobs green and names `smoke-windows` as *"green, not skipped"*. A
  storage bill blocked a merge whose contents were three documentation commits.
- **Wrote the retention split and V9 into `.github/workflows/ci.yml`.**
  `retention-days` is now
  `${{ github.event_name == 'pull_request' && 1 || 14 }}`. A pull-request build
  only has to outlive its own run, because `smoke-windows` downloads it seconds
  later; `main` builds are fetched days afterwards by `tools/fetch_build.py`,
  and for those 14 days is already tight. A `workflow_dispatch` run matches
  neither branch of the expression and keeps 14 days, which is right: a manual
  run exists to regenerate an artifact somebody is waiting on. `workflow_dispatch`
  itself is V9, one line copied from `deploy-website.yml:21`. The file still
  parses as YAML with all five jobs intact.
- **Upgraded to GitHub Pro**, which raises included artifact storage from
  500 MB to 1 GB.
- **Submitted the Apple Developer Program enrolment.** Individual / Sole
  Proprietor, mid-afternoon 2026-08-27. This is the first time enrolment has
  been started, and this line is the first record of it anywhere in the
  repository, which the 08-25 review's B1 acceptance asked for explicitly.
- **Established that A2 is gated, not misconfigured.** Xcode offers only
  "Apple Development" because creating a Developer ID Application certificate
  requires the Account Holder role *and* an active paid membership. Before
  approval, only the free Personal Team exists. A4, the App Store Connect API
  key, is gated identically. A3 is not gated and works with any account.

## Decisions made

- **Split retention by event rather than shortening it globally.** Shortening
  the window for everything would have hit `tools/fetch_build.py`, whose whole
  workflow depends on a `main` artifact surviving days. The pull-request half
  was the part that was never earning its storage.
- **Upgrade to GitHub Pro.** Brent's call. Worth recording alongside it: Actions
  is unmetered on public repositories using standard runners, minutes and
  storage both, so B5 makes this category of problem disappear on its own.
- **Do not create an "Apple Development" certificate as a stand-in.** It signs
  successfully and then fails notarization, which the runbook calls *"the single
  most common wasted afternoon in this process."* The failure would not surface
  until A7.
