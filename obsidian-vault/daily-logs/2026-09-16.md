## What got done

- **PR #17 merged as `4b942f4`** (`1f50ac1`, 2026-09-14 23:04 CDT). Snowpack
  Survey wolverine den-site minigame: `SnowpackProfile` (RefCounted) —
  IACS grain enum, five-step hand hardness, a seeded generator over five
  scenario families, three denning criteria as named consts; `SnowpackMinigame`
  (BaseScreen) draws the pit, grain as hatch symbols rather than color, a
  ruler, a legend, and the verdict on the data axis. Bound to F3 in `main.gd`
  with the same modal guard the credits screen uses. 25 GUT tests added in
  `snowpack_profile_test.gd`. Suite: 25 scripts / 269 tests / 4,172 asserts
  to 26 / 294 / 6,312, `docs/testing-setup.md:70` updated in the same commit
  so `suite_figures.py --check` stayed green. Five of five checks passed.
- **PR #18 merged as `d686d92`** (`e7e5b76`, 2026-09-16). Adds an optional
  `card_image` field to `sub_areas.json` (`docs/data-schemas.md` §4);
  sub-area 7 (Bow Valley) is the first to set it, pointing at the new
  `world_map_bow_valley.png` sprite, and `world_select_controller.gd`'s
  `_draw_sub_area_card` draws that texture tinted by lock state, with a
  label scrim for legibility, in place of the flat color fill. The other
  eleven sub-areas keep `card_image: null`. Also fixes an accidental
  deletion of the `## Phase 3 — Economy + information` heading in
  `docs/roadmap.md`, and adds the `brent-ops` process block to root
  `CLAUDE.md` (read by `/next`, `/route`, `/daily`, `/log`, `/verify`,
  `/weekly`). Suite: 26/294/6,312 to 26/299/6,318. Five of five checks
  passed.
- **A dated decision landed inside PR #18's diff, in `docs/roadmap.md`
  (2026-09-15):** the Bow Valley card gets real art; the rest of the
  2026-08-06 look-only decision stands. States explicitly that this does
  not reopen **C1** (in-map segment renderer) or **C2** (hover highlight) —
  the world-select screen is still `MOUSE_FILTER_STOP`, still
  non-interactive, and still a flat card grid; only the card background
  changed from a solid fill to a texture.
- **PR #19 merged as `ec3fb8d`** (`cbff44c`, 2026-09-16). `CONTRIBUTING.md`
  and root `CLAUDE.md` both recommended `git config format.signOff true` to
  sign off commits automatically. Verified in a scratch repo that this
  config affects only `git format-patch`, not `git commit`, and silently
  does nothing for the latter — which is why PR #18's commit needed an
  amend and a force-push to pass the `DCO sign-off` check. Fix: a tracked
  `.githooks/prepare-commit-msg` hook that appends a `Signed-off-by`
  trailer built from the committer's git identity, skips merge commits, and
  is enabled per clone or worktree with `git config core.hooksPath
  .githooks`. Both docs now point at the working fix. Five of five checks
  passed.
- **This closed a live defect, not a hypothetical one.** `format.signOff
  true` was the documented instruction and had never worked; PR #18 is the
  first recorded case of it failing in exactly the way PR #19's fix
  describes, and my own standing memory of this rule (`feedback-dco-signoff`)
  already carries the corrected version.
