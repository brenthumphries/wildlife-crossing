## What I worked on

Wrote and iterated on the first PRD for the game: the wildlife overpass crossing
feature. Conducted a structured interview to gather requirements, then refined the
document through several rounds of feedback that meaningfully changed the
underlying design model.

## What got done

- Created `obsidian-vault/prd/wildlife-overpass-crossing.md` — the first PRD in
  the vault, covering the overpass crossing structure as a v1 feature.
- Established the two-terrain-category model: hard barriers (fences, walls,
  buildings, urban zones) are impassable; hazardous tiles (roads, rivers) are
  passable but carry per-step mortality risk.
- Defined the per-terrain-type environment variable pattern for mortality
  probabilities (`ROAD_HAZARD_MORTALITY`, `RIVER_HAZARD_MORTALITY`).
- Resolved two design questions that were initially open: multi-tile spanning
  (player must tile across every cell) and default mortality rate (20% per step).

## Decisions made

- **Overpass only in v1.** Underpasses and corridors are out of scope for this
  PRD. The data model is designed to accommodate them later without structural
  changes.
- **Per-cell tiling for multi-tile barriers.** A single overpass tile does not
  span a wide river — the player must tile each cell. A partial span does not
  create a traversable connection.
- **Roads and rivers are passable, not impassable.** Animals can and will
  pathfind across them without a crossing, but risk dying on every step. This is
  a more ecologically accurate and mechanically interesting model than making them
  hard barriers.
- **Per-terrain mortality env vars.** Each hazardous tile type has its own
  environment variable and default, allowing independent tuning without code
  changes. Default for both is 0.20.
- **Species crossing preference is P1, not P0.** The `preferred_crossing_type`
  field on species is in scope but not required for the feature to ship.
