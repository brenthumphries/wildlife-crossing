## Also this session: review authority and the merge gate

### What got done

- **[ADR 0019](../../docs/adr/0019-dco-sign-off-on-automated-commits.md) is
  `superseded-by-0020`.** Its Context and reasoning are untouched, because they
  are why ADR 0020 took the migration path ADR 0019 had already named for
  itself.
- **Everything in the Next session block above has landed.** PR #9 `37bd3a5`
  (the vault three), PR #10 `a8bc28c` (ADR 0020 and its pointers). Ten pull
  requests merged in project history now, three of them today.

### What the analysis found

- **Auto-merge answers when, never who.** It cannot bypass ruleset `22403399`,
  it waits for all five contexts, and the enabling click is the product
  owner's. It does not contradict ADR 0019's claim that "nothing signed in
  advance enters the project without the product owner's merge", which says the
  product owner's merge rather than a click at the moment CI turns green. The
  concern raised against it on 09-08 was looser than the ADR is.
- **The real gap is that there is no review gate at all.**
  `required_approving_review_count: 0`, `require_code_owner_review: false`,
  `require_last_push_approval: false`, and no `CODEOWNERS` file. The rule that
  the product owner decides what merges is currently enforced by there being
  exactly one writer, which is a property of the membership rather than of the
  configuration.
- **ADR 0019 blocked the obvious fix.** GitHub does not let an author approve
  their own pull request, and ADR 0019 made every automated commit the product
  owner's, so a required review could never gate automated work.
- **ADR 0019's own escape hatch does not fit the current ruleset.** It puts the
  trailer in the squash-merge message; `allowed_merge_methods` is `["merge"]`
  only. ADR 0020 D2 uses the merge commit body instead.
- **`require_last_push_approval` is the precise hole**, sharper than
  `dismiss_stale_reviews_on_push`: it is what stops an approval being followed
  by a push that auto-merge then lands.

### Decisions made

- **D1 and D2 approved by Brent.** The pipeline gets its own machine account,
  and ADR 0019's attestation moves to merge time. D3, that self-authored pull
  requests are gated by checks alone, was written as a description of a residue
  rather than a choice and was not separately ruled on.
- **A second personal login for reviewing was considered and rejected.**
  GitHub's terms allow one free account per person plus a machine account that
  "can only be used for running a machine", so it is not available. The
  deciding objection is not the policy: an approval from an account the author
  controls certifies nothing the author's own judgment did not, which is the
  failure ADR 0019 already refused one layer down when it rejected a bot
  signing the DCO as itself.
- **Two doc-pointer edits were added to the ADR pull request unasked**, on the
  argument that landing a supersession while two documents still assert the
  superseded rule manufactures a §4 drift row. Accepted.

### Open questions / blockers

- **The machine account does not exist.** D1 and D2 are accepted and

- **The ruleset changes are keyed to an event, not a date.** `CODEOWNERS`,
