## What I worked on

ATT-67: a workflow that launches the published v0.1.0 Windows and Linux binaries and captures their title screens, so the automatable half of B7 (ATT-62) no longer waits for a machine.

## What got done

- **2026-10-25: added `.github/workflows/binary-check.yml`.** Manual trigger only (`workflow_dispatch`, input `tag`, default `v0.1.0`), read-only token, two jobs.
  - Both jobs download the Release assets with `gh release download` and the repository's `GITHUB_TOKEN`, then run `sha256sum --check --ignore-missing` against the Release's `SHA256SUMS.txt`, so the bytes launched are the bytes that were signed for.
  - **Linux** (`ubuntu-latest`): Xvfb at 1280x720, Mesa llvmpipe, binary launched for at least 10 seconds, screenshot with ImageMagick `import`.
  - **Windows** (`windows-latest`): binary launched at 960x540 (runner screens default to 1024x768), screenshot with `System.Drawing` `CopyFromScreen`, graceful close so the log flushes.
  - Each job uploads `title-screen-linux` or `title-screen-windows` (PNG plus launch logs, 14 days) and writes a table to the run summary: still running, logged `Title screen ready`, screenshot taken, flat-colour check, `ERROR:` count, renderer line.
- **Renderer fallback.** `game/project.godot` already pins `gl_compatibility`, so Vulkan is never used and there is no Vulkan-to-OpenGL step to add. Both jobs pass `--rendering-method gl_compatibility --rendering-driver opengl3` explicitly so a later project change cannot turn this into a Vulkan check. The real fallback is Windows: a runner with no GPU has only OpenGL 1.1, so the job retries with `--rendering-driver opengl3_angle`.
- **YAML lint.** `yamllint` and `actionlint` are not installed here. The file parses with PyYAML, and the four bash `run` blocks pass `bash -n`. The PowerShell block was not parsed (no `pwsh` here).
- Nothing signed, tagged, released, published or deleted. `game/export_presets.cfg` untouched. Nothing committed; the commit plan is `commit-plan-2026-10-25-att67.json`.

## Decisions made

- **Screenshot by screen capture, not by an engine flag.** It shows what a user's window shows, which is what B7 asks. The cost is that it depends on the runner having a desktop; if it does not, the job fails with an annotation and ATT-62 stays open for that platform.
- **The Windows job reads the title line after closing the window, not while it runs.** A release template does not flush stdout when it is redirected to a file, so the line can sit in the buffer until exit.
- **A pass is not a verdict on the image.** The job proves the process stayed up, logged the title line and produced a screenshot. Brent still looks at the two PNGs.
