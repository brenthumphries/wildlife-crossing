## What I worked on

Getting ten unpushed commits onto GitHub and through CI for the first time, then
fixing what broke on the way. Four threads in the order they surfaced: the
`ci.yml` `retention-days` defect, the Windows smoke gate, the first end-to-end
walk of the push runbook, and the tooling to stop that runbook rotting again.

## What got done

- **Closed build-review B1.** `retention-days: 14` sat as the last line of the
  `smoke-windows` `run:` block under `set -euo pipefail`, so the job exited 127
  before it ever touched the binary, and the `Upload build artifacts` step had
  lost the key it still carried on `origin/main`. Moved back under `with:`
  (`13857e0`). Verified after the edit rather than by eye: the file parses as
  YAML with `retention-days` as an integer key on the upload step, and the
  `smoke-windows` run block passes `bash -n`.
- **Pushed `feat/save-load-and-agent-respawn` and opened PR #1.** Branch pushes
  fire nothing (`ci.yml` triggers only on `push` to `main` and `pull_request`
  targeting `main`), so the pull request is what ran CI. Run `31760975487` was
  the first in project history to execute five jobs: `Tool tests`,
  `DCO sign-off`, `GUT tests` and `Export desktop builds` green,
  `smoke-windows` red.
- **The Windows binary is healthy. The gate was not.** Both boots reached their
  expected state, `Title screen ready` and `Tutorial loaded`, and both ended at
  exit 124, which is the healthy path `smoke_boot.sh` is built around. All 53
  `ERROR:` lines across the two boots are at-exit engine diagnostics:
  unreferenced static strings, the two engine NavMesh parser RID types, Variant
  pool pages in use. None come from game code. The Linux boot of the same commit
  logged zero, so the difference is Windows running more of Godot's
  static-destruction path when killed.
- **Fixed it by allowlisting** (`6db1e3d`). `BENIGN_PATTERNS` in
  `tools/smoke_boot.sh` is stripped before `FATAL_PATTERNS` are counted, and the
  number of lines stripped prints on every run. Entries are narrow on purpose:
  the RID entry names the two engine parser types observed rather than the
  generic `were leaked at exit.`, so a leak of a game type still fails.
- **Added `tools/tests/test_smoke_boot.py`**, 11 tests driving `--check-log`, no
  engine or export needed. Eight are the failing side, including the
  allowlist-tightness cases. Three of the 11 fail against the unpatched script.
  Nothing had covered `smoke_boot.sh` before, which is how a gate that could not
  pass shipped.
- **CI green.** Run `31762062722`, all five jobs.
- **Walked the push runbook's Steps 4 and 5 end to end for the first time. Four
  of its commands could not work as written.** `gh run download` into the fixed
  `~/Downloads/wc-latest-build` aborted with `file exists` against a previous
  download. `xattr -dr com.apple.quarantine wildlife-crossing.app` failed with
  `No such file`, because Godot names the bundle from `config/name` in
  `project.godot`, so it is `Wildlife Crossing.app`, space and capitals, not the
  export path that produced `wildlife-crossing.zip`. Step 1 omitted `-s`, which
  the DCO gate added in `792b237` would reject. Steps 2 and 3 never said that a
  feature-branch push runs no jobs at all.
- **Wrote `tools/fetch_build.py`** (`10062ad`) so Step 4 stops being prose. It
  downloads into a directory named for the run, refuses a destination that
  already holds something, unpacks with `unzip` rather than Python's `zipfile`
  (which preserves neither the symlinks nor the executable bit an `.app` needs),
  globs for the bundle and binaries, and prints Step 5's commands with the real
  paths already shell-quoted. 17 tests, none touching the network. Every fixture
  bundle is named `Wildlife Crossing.app`, since one named
  `wildlife-crossing.app` would pass while proving nothing.
- **Corrected the runbook** (`4119915`): the missing `-s`, the CI trigger facts
  in Steps 2 and 3, all five job names in Step 3, `fetch_build.py` in Step 4,
  and a rewritten Step 5 carrying the `codesign` check, the title screen
  [ADR 0017](../../docs/adr/0017-licensing.md) put in front of the tutorial, F1
  credits as the licensing obligation it is, and an F5 / quit / relaunch / F9
  round-trip.
- **Launched a windowed macOS build from current `HEAD`.** It ran. First time
  any human has seen a build of this commit.

## Decisions made

- **Fix the smoke gate by allowlisting, not by loosening.** `smoke_boot.sh`'s own
  note says to allowlist the specific string rather than drop the check, on the
  grounds that a gate which cannot fail is what produced the original defect.
  Followed it, and made the filter report its own count so the list cannot grow
  quietly.
- **Make Steps 4 and 5 mechanical rather than only correcting them.** Brent's
  call when offered the cheaper option. Prose can rot silently; a glob with a
  test cannot. `check_pck_contents.py` had already learned this lesson and the
  runbook had re-introduced the same defect in prose, where nothing could catch
  it.
- **Push the branch before committing the outstanding build-review docs.**
  Brent's call. Since a branch push runs no CI, it cost nothing and gave an
  off-machine backup partway through the session.

## Open questions / blockers

- **B2 is not closed by its own acceptance.** It asks for
  `git rev-list --count origin/main..HEAD` to reach 0. The ten commits are on
  `origin/feat/save-load-and-agent-respawn`; `origin/main` has not moved since
  2026-08-10. PR #1 is open, green, and unmerged. Merging it closes B2.
- **B3 is advanced, not closed.** All three packs passed the contents gate and
  both the Linux and Windows binaries boot in CI, but the windowed checklist was
  not walked: `B`, `M`, `F1`, left-click, `Enter`, `Escape`, `F5` and `F9`,
  credits legibility and scrolling, the crossing cue and its chime are all
  unconfirmed. Quicksave to `user://` has still never run from an exported
  binary.
- **V5 is half done.** The `dco` job executed for the first time and passed. Its
  acceptance also requires observing it red on a deliberately unsigned commit,
  which has not happened.
- **Whether the macOS `.app` needed a local ad-hoc signature is unrecorded.** It
  launched, but the `codesign -dv` output was never read back, so whether
  Godot's built-in signer produces a usable signature from a Linux runner is
  still unknown. That is exactly the evidence C1 and
  [ADR 0018](../../docs/adr/0018-code-signing-and-notarization.md) want.
- **The stale `.git/index.lock` is not what the runbook says it is.** Its
  troubleshooting section still blames the `weekly-build-review` harness. The
  real cause, as far as the Cowork mount is concerned, is that the mount forbids
  `unlink`, so every git command leaves its lock behind. Uncorrected in this
  pass.
- **`docs/push-runbook.md` says "2026-08-14" at lines 134, 266 and 301** while
  the work is dated 2026-08-13 local. Cosmetic, already committed, worth a
  one-line fix on the next docs pass.
- **Three vault files are uncommitted** as this is written: this log,
  `obsidian-vault/build-reviews/2026-08-12-next-build.md` (two amendments), and
  `obsidian-vault/build-reviews/README.md` (revised headline). They want a
  `docs(log)` commit and a push to the same branch.
