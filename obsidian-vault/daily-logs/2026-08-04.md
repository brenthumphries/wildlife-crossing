## Also this session: wildlife simulation module

Separate thread, delivered from an isolated container conversation ("Using
expiring tokens wisely") with no access to this repo. Landed as three
drop-in zips this evening: `wildlife-crossing-spawn-mechanics.zip`,
`wildlife-crossing-pathfinding-logic.zip`, and
`wildlife-crossing-serialization.zip`, each a checkpoint of the same
growing module.

### What got done

- **A self-contained `wildlife/` module, not yet in the repo.** Extracted
  and inspected this session: the final package is 5,034 lines across 21
  GDScript files (`core/`, `core/pathfinding/`, `core/persistence/`,
  `adapters/`, `tests/`, `validation/`). Re-ran its own suites here: 90
  Python invariant and parity checks across three files, 28 in
  `test_twin.py`, 33 in `test_path_twin.py`, 29 in `test_save_twin.py`, all
  passing, plus `gdlint.py`'s structural check, 0 problems found.
- **Fixed the population model's first design bug.** Its own balance probe
  showed roadkill wasn't limiting anything: a crossing bought +2.5%
  population, lane count made no difference, and there was no recovery arc.
  Root cause was logistic growth refilling whatever the road removed. Fix:
  carrying capacity now depends on habitat connectivity, with a per-species
  sensitivity exponent, so a severed landscape supports fewer animals even
  at zero mortality. Crossings are now worth roughly +50% population and
  produce an 8 to 15 year recovery curve.
- **Caught a 240x unit error twice.** `growth_rate` and `mobility` were
  authored per tick instead of per year (240 ticks per year), in both
  directions, before landing on annual authoring for both.
  `SpeciesProfile.validate()` now rejects values large enough to be
  suspected per-tick figures.
- **Fixed the pathfinding layer's own design bug.** `PermeabilityBaker`
  originally asked whether an animal could cross a boundary rather than
  what crossing costs. Under that model, fencing an entire highway and
  building one cheap culvert gave every species 100% crossing usage and
  zero deaths: the game solved itself in one move. Fixed by pricing detour
  (`ideal_cost / actual_cost`) and by measuring road-crossing risk only
  along the route animals actually take, not averaged across fenced tiles
  nothing ever touches.
- **Added `detour_tolerance` as a per-species field.** Confirmed in
  `data/species/species.json`: deer 60, bear 150, salamander 3, fox 25. The
  module's `CLAUDE.md` records the resulting 50%-voluntary-use crossing
  spacing per species: bear about 140 tiles, deer about 62, fox about 21,
  salamander about 14. Different species now need genuinely different
  interventions: salamanders won't detour to an unfenced tunnel at all, so
  fencing is wasted on deer but essential for them.
- **Used Godot's own `AStarGrid2D` instead of a GDScript A* implementation.**
  Its `weight_scale` multiplier applies exactly where the validated cost
  model expects it; only the cost model itself was validated in Python.
- **Save/load layer: `SaveCodec`, `SaveDocument`, `SaveMigrations`,
  `SaveManager`.** Confirmed the atomic-write sequence in
  `save_manager.gd`: write to a temp file, read it back and verify its
  checksum, move the previous save to `.bak`, then rename the temp file
  into place; `load_game()` falls back to the `.bak` automatically if the
  main file fails to verify.
- **Found three real bugs in its own already-delivered code.**
  `CrossingGrid`, added in the pathfinding pass, had no `save_state()` at
  all, so a save would have silently dropped the entire tile world. The
  existing save/load test round-tripped dictionaries in memory and never
  touched JSON or a file, so it proved nothing; rewritten to go through
  real text, which exposed that Godot's `JSON.stringify` shortens floats
  and breaks bit-exact replay (populations still reconverge, since logistic
  growth is self-correcting, so this doesn't rot a save, but it does break
  reproducibility). `PopulationField` stored `PackedFloat32Array`; once the
  Python twin was corrected to match that precision instead of running
  float64 throughout, it showed a roughly 0.001% population leak over 83
  simulated years. Confirmed the fix in `population_field.gd`: population
  data is now `PackedFloat64Array`; tile data in `crossing_grid.gd` stays
  `PackedFloat32Array`, where the memory actually matters (about 1.2 MiB
  per layer on a large map).
- **The v2 to v3 save migration drops old region-edge road data rather than
  importing it.** Confirmed in `save_migrations.gd`: those numbers predate
  `PermeabilityBaker` and would reintroduce the two-sources-of-truth
  problem the baker exists to remove. A migrated save is flagged
  `needs_rebake`.

### Decisions made

- **Nothing derived is saved.** Edge permeability, connectivity, and
  capacity all rebake from tiles on load, so there is exactly one source of
  truth for road data: the tiles themselves. `RegionGraph.set_edge_road()`
  is no longer meant to be called from game code; painting tiles and
  letting the baker run is the only path now.
- **Tile data stays 32-bit; population data moved to 64-bit.** Sized to
  where each actually matters: tiles are large (about 1.2 MiB per layer)
  and don't need the precision, the population field is small and the
  precision loss was a real conservation leak.

### Open questions / blockers

- **Nothing here has touched this repo or the Godot engine yet.** The
  module exists only as three zip files from a separate, isolated
  conversation with no repo access. It is not in `game/systems/`, and every
  claim above is verified by a Python twin, a parity check, and a
  structural linter, never by actually running Godot, which the session
  that produced it named as its own top recommended next step.
- **Path requests are budgeted at 12 per tick**
  (`AgentSampler.PATH_BUDGET_PER_TICK`, confirmed). Large herds may visibly
  freeze after a big demolition; that constant is the knob.
- **Baking runs for every registered species on every tile edit.** Fine at
  four species; flagged in the module's own `CLAUDE.md` as needing
  profiling once there is a road-drag tool.
- **`home_range` must be calibrated per map**, via
  `ConnectivitySolver.suggest_home_range()` run on an unroaded test map,
  not guessed.
- **Predator-prey coupling and a true salamander mass-migration pulse**
  (every adult crossing on one spring night, named in the module's
  `CLAUDE.md` as the best showcase for the culvert mechanic, currently only
  approximated by a seasonal affinity spike) are the two gaps the module's
  own docs call out first.
- **Not yet reconciled with the rest of the repo's docs.** `game/CLAUDE.md`'s
  systems table and `docs/architecture.md` don't list this module, the same
  doc-drift pattern today's build review flagged for `hud.gd` and
  `build_mode.gd`.
