## What got done

- **Made the v0.1.0 scope call — build-review B2** (`7ae676a`, +74 lines to
  `docs/roadmap.md`). The item existed because C2–C5 of the 07-28 review went
  quiet rather than being closed or deferred on the record. Both halves are now
  written down in the same form as the 2026-07-29 Bow-Valley entry. See
  Decisions below.
- **Fixed the blind world-map click** (`cb9f9b8`).
  `game/scenes/ui/WorldSelectMap.tscn` was `mouse_filter = 2`
  (`MOUSE_FILTER_IGNORE`), so a click on the opaque card grid fell through to
  `Main._try_select_segment()`, which resolves the cursor against the **world**
  camera hidden underneath. In segment mode that could open the confirm panel
  on a Bow Valley segment the player never aimed at. Now `mouse_filter = 0`
  (`STOP`).
- **Moved mouse handling to `_gui_input` in the same change**, because `STOP`
  reroutes events there. Without that, **scroll-to-zoom would have died
  silently** — and it is a Phase 2 exit criterion, so the fix would have traded
  one invisible defect for another.
- **Wrote three regression tests** in `world_select_controller_test.gd`:
  `test_world_select_map_scene_stops_mouse_events`,
  `test_left_click_in_segment_mode_selects_nothing`, and
  `test_scroll_wheel_still_zooms_through_gui_input` — the last one being the
  guard on the trade just described.
- **Suite green at 18 scripts / 147 tests / 2,806 asserts** (was 144 / 2,799 at
  the 08-04 review). Headless boot from source clean. *Both figures quoted from
  the commit message.*
- **Documented why `_try_select_segment()` is still there.** Added a docstring
  above it in `game/scripts/main.gd` (`:156-162` as of 2026-08-10; the 08-09
  boot-flow commit shifted it) stating it is unreachable from the map
  screen in v0.1.0, pointing at the roadmap decision and at build-review C1 as

## Decisions made

- **The world map ships look-only in v0.1.0.** Recorded at
  `docs/roadmap.md:138-165`.
  - **C1, in-map segment renderer → deferred to Phase 2 completion.** It is
    named nowhere in the roadmap — neither in Phase 2's Implements list nor its
    exit criteria. It entered the reviews as the fix for the click defect, and
    that defect is now closed a cheaper way.
  - **C2, hover highlight → deferred to Phase 2 completion.** A P0 requirement
    in Phase 2's Implements list and a named P0 test in `test-plan.md:172`, but
    not one of the five exit criteria, so Phase 2 can be judged met without it.
    Deferred on *dependency*, not priority — it needs C1's in-map render to have
    something to hover over.

    *(The decision text as written cites `roadmap.md:85` and `:98-108`. Those
    were correct when written and are not now: this session's own +74-line
    insertion pushed them down. Read the decision block itself, not the line
    numbers inside it.)*
  - **C3 (written QA pass) and C4 (tutorial measurement) ship in v0.1.0.**
- **The `mouse_filter` change is a stopgap with an expiry.** It makes the defect
  unfireable rather than correct: `B` remains the placement path and the map
  screen is decorative. C1 supersedes it, and C1's acceptance still requires
  that the drawn map and `_pick_segment_at_mouse()` agree on a coordinate space.
- **Both Phase 1 P1 items deferred past v0.1.0** — species-preference weighting
  *and* the crossing usage counter (`docs/roadmap.md:73-79`). Only the first had
  ever been recorded as a deferral, which left the usage counter silently
  unbuilt across five consecutive reviews. Re-verified the same day:
  `preferred_crossing_type`, `usage_count` and `times_used` all return zero hits
  in `game/scripts/`. Rationale: neither is in Phase 1's exit criteria, and a
  usage counter over a build with one playable crossing counts to one.
- **Kept `_try_select_segment()` wired rather than deleting it**, with the
  docstring carrying the reason. Deleting correct, tested logic to express a
  scope decision would have cost it twice.
