## Decisions made

- **`BaseScreen` debt is paid down for new UI, not retrofitted onto old UI.**
  `Hud` is the first thing to extend `base_screen.gd`; `ConfirmPanel` and
  `ConnectivityOverlay` keep their own ad-hoc `_build_ui()` patterns. Brent's
  call, weighed against migrating all three now — retrofitting working,
  tested UI for a convention-only change was judged not worth the scope
  increase on an otherwise `M`-sized item with nothing else queued behind it.
- **`BaseScreen` is a script base, not a `.tscn`.** The convention as written
  in `game/CLAUDE.md` assumes scene-authored UI; this project has none — every
  screen is instanced with `.new()`. A `.tscn` with nothing in the editor to
  show for it would be dead weight, so the base is a plain script class,
  consistent with how `ConfirmPanel`/`ConnectivityOverlay` already work.
- **Placeholder cue art is a generated PNG, not a procedural `_draw()`.**
  Brent's call between the two candidate approaches. A real (if temporary)
  sprite file exercises the actual `TextureRect` + asset-loading path the
  final art will use, rather than a code path that would need to be thrown
  away once real art lands.
- **The HUD mirrors `_log()` rather than replacing it or duplicating call
  sites.** `Debug` stdout logging is unchanged — still the primary channel
  for headless/CI diagnosis (`tools/smoke_boot.sh` reads it directly). The
  HUD is strictly additive, wired through the one existing chokepoint
  (`Main._log()`) so no future `_log()` call needs a matching HUD call.

## Also this session — first AI-generated art pass (all eight species portraits)

Separate thread from C1: tried **Nano Banana** (Gemini image model) as a source
for art assets, working from [[../design/art-direction]]. Produced a reusable
prompt-template set and a first-pass portrait for every launch species. All of it
lives in `docs/prompt-templates/wildlife-crossing-portraits-1024/`.

### Asset selection — why portraits and not tiles

Deliberately did **not** target the P0 tileset or sprite sheets. Nano Banana has
no concept of a fixed canvas grid, seamless tile edges, or frame-to-frame
consistency, so a 32×32 flat-top hex that must tile on six edges, or an idle/walk/
cross cycle with a stable silhouette, would come back as an attractive image that
fails the actual constraint. The **64×64 inspect-panel portrait** (art-direction
§5, P1) is the only asset in the doc with none of those constraints — single
centered subject, no tiling, no animation — so it was the honest first test.

### What got done

- **Eight prompt templates**, one per species: `nano-banana-species-portrait.md`
  (grizzly — also the canonical template, holding the workflow, downscaling steps
  and rationale) plus seven `nano-banana-portrait-<species>.md` instances. Each is
  a self-contained paste with subject/style/composition/exclusion blocks, a
  species-specific failure mode, and an acceptance checklist.
- **Eight palette reference PNGs** — a shared `wildlife-crossing-palette.png` and
  seven per-species `palette-<species>.png`, each carrying a fur ramp, feature
  colors, and the parchment background, generated from the art-direction §2 hexes.
- **Eight 1024-target portraits generated and kept**: grizzly bear, elk,
  pronghorn, mountain caribou, wolverine, gray wolf, Canada lynx, bighorn sheep.
  Workflow that worked: fresh Gemini chat per species, palette PNG as the only
  attachment, prompt pasted unmodified.

### Decisions made

- **Per-species palettes omit the data-axis and `#C0492F` swatches** that the
  shared palette carries. Image models don't reliably process negation in a
  reference image, and for the tan/amber species (elk, pronghorn, bighorn) the
  orange stops `#E08A3C`/`#D9A85C` sit close enough to correct fur tones to invite
  contamination. The prohibition lives in prompt text only.
- **Attach the palette PNG, never `art-direction.md` itself.** Long design docs
  dilute an image prompt — the model treats them as context to summarise rather
  than constraints to obey. Every constraint that matters is inlined in each prompt.
- **Predator portraits keep the "calm and alert, not aggressive" line.** The cozy
  pillar (§1) applies to wolves and wolverines too; models default to snarling.

### Open questions / owed

- **Per-species fur ramps are a proposal, not a spec.** art-direction §5 gives each
  species a one-line distinguishing read and no colors; the ramps were derived from
  those lines plus `obsidian-vault/wiki/` ecology, harmonised to the §2 register.
  **Owed: fold them back into art-direction §5 as a logged decision** once enough
  portraits exist to judge them side by side.
- **These are concept references, not shippable assets yet.** Measured: every file
  is **2048×2048 RGBA with 11,000–25,000 unique colors** — Nano Banana renders
  *pixel-art-looking* imagery, not a true pixel grid. The nearest-neighbor downscale
  + 16-colour quantize step in the template is therefore mandatory, not optional,
  and hand-fixing eyes/ear-edges at 64×64 should be assumed for every species.
- **Two naming nits to clean up before these are referenced from code:** the folder
  is named `...-1024` but the contents are 2048×2048, and
  `gray-wolf-portraint-1024.png` is misspelled.
- **Nothing is wired into the game.** No `game/assets/sprites/portraits/` yet, and
  no consumer — the inspect panel doesn't exist. These are ahead of their consumer
  on purpose.
- **Untested against the harder asset classes.** Whether Nano Banana can contribute
  anything to the P0 tileset or the three overpass biome variants is still an open
  question; the constraints above suggest not, but it hasn't been tried.
